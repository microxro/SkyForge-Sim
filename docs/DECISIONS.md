# Architecture decision records

## ADR-0001 Working branch
- Context: §0/§23 ask for branch `skyforge/main-build`. This cloud session is configured to develop and push only on `claude/ecstatic-davinci-tjahz4`, and pushing elsewhere needs explicit permission.
- Options: (a) push to `skyforge/main-build` anyway, (b) use the session branch.
- Decision: (b). All work and the single pull request use `claude/ecstatic-davinci-tjahz4`. Wherever the directive says `skyforge/main-build`, read the session branch.
- Consequences: the user can rename the branch on GitHub later if wanted; nothing else changes.

## ADR-0002 Resume mechanism
- Context: §2.3 asks for a recurring "SKYFORGE resume" scheduled task. Earlier in this session the user had a scheduled task deleted and asked for the `autoContinueAtUsageLimit` setting instead.
- Decision: honour the user's explicit choice: no scheduled task; `autoContinueAtUsageLimit: true` plus the project Stop hook. Fallback for a fresh session: send "continue".
- Consequences: a session that ends entirely (not just paused by a limit) needs the user to send "continue".

## ADR-0003 Runtime shader compilation
- Context: Xcode 26 ships the Metal toolchain as a downloadable component; CI runners have failed with "missing Metal Toolchain" (runner-images #13080).
- Decision: no `.metal` files. MSL lives in Swift strings under `SFRender/Shaders/` and is compiled with `MTLDevice.makeLibrary(source:options:)`, cached; `MTLBinaryArchive` later.
- Consequences: first-use compile cost hidden behind a loading screen; shader compile test on macOS CI.

## ADR-0004 Hand-written Xcode project with XcodeGen fallback
- Decision: commit a minimal objectVersion 77 project with one synchronized `App/` folder and one local package product (`SkyforgeUI`). `project.yml` mirrors it for a CI fallback. Linux lint: `tools/lint_pbxproj.py`.
- Consequences: first real validation happens on macOS CI or Mac day.

## ADR-0005 Local Swift toolchain version
- Decision: Linux uses Swift 6.3.3 to match the Swift 6.3 compiler in the Xcode 26.6 CI pin, reducing language-version drift between Linux and Apple builds. Package declares tools 6.2.

## ADR-0006 Elementary math functions
- Decision: pure targets import Foundation for `sin/cos/atan2/pow/exp` (available on Linux via swift-corelibs-foundation). No `simd` module; stdlib `SIMD3<Double>`.

## ADR-0007 PNG output and compression
- Decision: `SFPreview.PNGEncoder` writes stored (uncompressed) deflate blocks with no dependencies. Committed PNGs are recompressed by `tools/png_compress.py` (Python stdlib zlib, a build tool, not shipped) to keep the repo small.

## ADR-0008 App icon generation
- Decision: the icon is generated by `swift run sfpreview icon <out> <size>` (pure Swift, shares the PNG encoder) instead of a separate `tools/make_icon.swift` script that would need CoreGraphics. Sizes: iOS 1024 universal + all macOS sizes.

## ADR-0009 Free / non-commercial
- Decision: SKYFORGE stays free with no ads, in-app purchases or subscriptions, which keeps Open-Meteo's free non-commercial terms applicable (§9.6).

## ADR-0010 Flight model frame and thrust
- Decision: the FDM integrates in a local NED tangent plane (flat Earth); the orchestrator re-anchors the origin (≤ 10 km) and converts to ECEF for rendering. Thrust uses T = ηP/√(V²+V0²) with V0 = η/k_static (smooth static-to-cruise transition) until the BEM propeller table lands.
- Consequences: Earth curvature and rotation are ignored inside a 10 km cell (error well below other model uncertainty for GA speeds).

## ADR-0011 CLI target name
- Decision: the preview CLI target is `SFPreviewCLI` (product `sfpreview`), because `sfpreview` and `SFPreview` collide on case-insensitive macOS file systems. `tools/check_paths.py` guards against case-only collisions.

## ADR-0012 Five-hourly "continue" pulse
- Context: the user, on 2026-11-08, asked for a command that sends "continue" every 5 hours, in addition to `autoContinueAtUsageLimit`.
- Decision: a session-bound scheduled task (`trig_01VkukC5znseCkMfBGwFqndn`, cron `33 */5 * * *` UTC). This supersedes the "no scheduled task" part of ADR-0002 at the user's explicit request.
- Consequence: an idle session is woken at most every 5 hours; the Stop hook still drives continuation while a turn is running.

## ADR-0013 Physically based sky: CPU reference first
- Context: §8 asks for Hillaire sky LUTs on Metal; this host has no Metal device and CI's device availability is unknown.
- Decision: implement the Hillaire 2020 model in Swift (`SFAtmosphere/Scattering.swift`) with the paper's Earth parameters (Rayleigh 5.802/13.558/33.1 ·10⁻³ km⁻¹, H 8 km; Mie 3.996/4.40 ·10⁻³ km⁻¹, H 1.2 km, g 0.8; ozone tent at 25 km), test it on Linux, use it for CPU previews, and treat it as the oracle for the MSL compute port (P1.5b), compared texel-by-texel by the visual-regression harness when a device exists.
- Consequence: the sky is correct and testable everywhere today; the GPU path cannot drift silently.

## ADR-0014 Real orthoimagery for ground realism
- Context: the user compared SKYFORGE with MSFS 2024 and asked for realism; procedural colour alone cannot reach that look. MSFS's ground comes from licensed aerial imagery, which is not available to us.
- Decision: free sources only, without keys or accounts: USGS orthoimagery (public domain, ≈0.3–1 m, US) and Sentinel-2 cloudless 2016 (CC BY 4.0, 10 m, worldwide). Pure-Swift baseline JPEG decoder so previews/tests run on Linux; tiles cached in the content store; land cover (water/forest/built-up) derived from colour drives water shading and 3D tree placement on top of the imagery.
- Consequence: US regions approach photographic ground detail; elsewhere 10 m imagery plus procedural detail. Attribution is required in the app (Settings → Attributions) for the Sentinel-2 layer.

## ADR-0015 Bold Mode: real-world airports by default, bundled showcase tile packs
- Context: the user's Bold Mode directive (docs/BOLD_MODE.md) asks for real-world airports as the default start, offline showcase airports, and streaming elsewhere. The bundle limit is 150 MB (MASTER_PROMPT §… bundle ≤ 150 MB).
- Decision: `TilePack` (SFContent) holds the recorded HTTP responses (imagery JPEG, Terrarium PNG) of a real-world load, content-addressed with a SHA-256 manifest. `TilePackTransport` serves pack hits and falls back to the network, so the loader is unchanged. `sfpreview pack-airport` records a pack at the phone tier.
- Six showcase airports, 43 MB in total (the bundle is ≈ 57 MB with the DEM and nav data):
  - KMRY Monterey (US coast, the default start);
  - KASE Aspen (US mountains);
  - KBFI Boeing Field (US city);
  - LSZS Samedan (Alps) and NZQN Queenstown (Southern Alps), Sentinel-2 only;
  - KCOI Merritt Island.
- Missing imagery tiles fall back to up to three coarser ancestors, so higher tiers fly offline on the packed zoom and partial caches still cover the ground.
- Other airports from the bundled OurAirports data stream after an explicit download prompt (Guideline 4.2.3). When a load fails, the app flies the offline SkyWorld airfield and says so on screen.

## ADR-0016 OSM data access from the build environment
- Context: A3 needs OpenStreetMap buildings and roads (ODbL). The cloud build environment's proxy refuses every OSM host: overpass-api.de, its mirrors, api.openstreetmap.org, planet and Geofabrik. overpass-api.de was added to the allow-list (approved by the user on 2026-11-08), but its TLS handshake is still reset upstream.
- Decision: the app queries Overpass at runtime (keyless and free, ODbL attribution on screen), and tests use fixtures. Showcase packs gain OSM layers once the build environment can reach an OSM source; until then they carry imagery and elevation only, and buildings fall back to procedural ones. Overture Maps is not used, because its building layer mixes in Microsoft ML footprints, which the directive forbids.

## ADR-0017 Sharp approach imagery from the USGS export endpoint (2026-11-08)
- Context: the art review found near-ground blur at US airports (KMRY, KBFI, KASE). The cause is the 3 m/px phone-tier mosaic magnified about 6× near the camera. USGS cached tiles (`USGSImageryOnly/MapServer/tile`) stop at z16. The NAIP ImageServer host (imagery.nationalmap.gov) is blocked from the build environment.
- Decision: `USGSImageryProvider` builds z17/z18 tile URLs from the same public-domain map service's `export` endpoint, using exactly the tile's EPSG:3857 bounds at 256 px. These tiles flow through the normal tile pipeline, cache and packs.
- Coverage: a third imagery layer, `detail`, covers a 2.4 km square centred 1 km out on the approach. At phone tier it is 2048 px (z17, about 1 m/px); on desktop 4096 px (z18 streamed; offline it falls back to z17 tiles).
- Grading and rendering: the layer is colour-matched to the near mosaic and feathered over its outer 8 % (Metal shader and CPU `ImageryGround` agree).
- Scope: US airports only. Sentinel-2 is 10 m native.
- Packs: KMRY, KASE, KBFI and KCOI re-recorded; showcase total 51 MB.
- Licence: USGS The National Map imagery is a US Government work (public domain). No key, no account.

## ADR-0018 Texture streaming for the sharp imagery layer (2026-11-08)
- The fixed z17 approach square (ADR-0017) became a camera-following z18 layer:
  - 1.2 km at 0.59 m/px on phone and tablet (2048 px); 1.6 km at 0.39 m/px on desktop (4096 px).
  - The region loads it around the start view. Once the aircraft drifts 40 % of the half extent, the app re-streams it centred 75 % of the half extent ahead.
- Loading: tiles come from the pack, then the tile cache, then the network. The texture and its mips are built off the main thread and swapped in on the render thread, so no frame stalls.
- Memory: one detail texture at a time (phone: 2048² RGBA + mips ≈ 22 MB).
- Evidence: CPU reference renders of the KMRY start view show the GPU sampling path is correct. The remaining softness at 170 m AGL is mostly photo trees and baked shadows at grazing angles, not texel size, so the gain is largest low on approach and on the ground.

## ADR-0019 Review-camera ground is source-limited, not magnification-limited (2026-11-09)
**Context**
- Art rounds 4–6 levelled off around 5.0–5.2.
- The art director attributed this to a magnified ~1 m/px photo filling the bottom 40 % of the frame. They proposed classified detail materials as the structural fix.

**Measurement**
- **Pixel footprint at the review camera:** the chase view on a 3° final is about 120 m above ground. There a bottom-row pixel spans about 0.4 m across by 1 m in depth.
- **Imagery resolution:** the z18 USGS layer is about 0.5 m/texel at these latitudes. The ground is therefore sampled at about 1:1, not magnified.
- **Effect of the materials layer (b7affb8):** it changed the lower half of every review frame by less than 1/255 on average. High-frequency energy was unchanged.
  - The anti-aliasing gate correctly keeps sub-metre octaves off pixels this large.
- **Sharpness is limited by the source:**
  - An earlier CPU reference already matched the GPU softness.
  - The USGS export at z18 is at or near the service's native resolution, so z19 would oversample.

**Decision**
- **Keep the materials layer.** It is cheap and correct, and it acts where the ground is magnified: runway start, cockpit view and low flight.
- **Stop treating near-ground sharpness as the lever for the review frames.** Sharper ground at this camera needs imagery sharper than ~0.5 m. Within the licence rules (keyless, Apache-compatible, no Bing/MSFS) no such source is reachable from the build environment: the NAIP host is blocked, and OSM is unreachable (ADR-0016).
- **The remaining levers** are lighting, atmosphere, buildings, trees and the aircraft.
- **Feasibility:** reaching 8/10 against commercial sims on real-airport frames may not be possible within these constraints. Any round that plateaus will be recorded here with its measurements, not hidden.
